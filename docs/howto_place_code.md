# サンプルコードを練習環境に置く方法

手順書のサンプルコードは、GitHubのページからコピーし、自分のPCの練習環境（`~/ws/`）のファイルに貼り付けて使う。そのまま貼り付けて使うことを想定しているので、コードを隅々まで暗記する必要はない。各行が何をしているかは手順書の解説を読んで理解し、書き方そのものは、必要になったときにサンプルを見返せばよい。この資料では、その方法を2つ紹介する。どちらか一方を使えればよい。

- **方法A: `touch` と `nano` を使う**（ターミナルだけで完結する。追加の導入は要らない）
- **方法B: VS Codeを使う**（Windows側のエディタで、WSLの中のファイルを直接編集する）

- 対象: フェーズ2の2-7節（雛形の `hello.py`・`hello.cpp` の文言を書き換える）以降で、ファイルを作る・書き換えるとき。サンプルコードを貼り付けるのはフェーズ3-1から
- 所要目安: 10〜15分（読み物＋1回の練習）

> **実行環境が無くても読めるように**: コマンドの直後に「期待する結果」として、表示の例と読み方を書いている。方法Aの `touch`・`ls`・`head` の表示は、使い捨ての環境で確かめたものと同じ形。`nano` とVS Codeの画面の様子は、それぞれの仕様から想定したもので、版によって細部が異なる。

## 1. 手順書のどこを見ればよいか

手順書では、サンプルコードの直前に、置く場所が次の形で書いてある。

```text
ファイル: `ws/src/learn_py/learn_py/talker.py`
```

この場合、`~/ws/src/learn_py/learn_py/talker.py` というファイルを作り、その下のコードブロックの中身を丸ごと貼り付ける。コードブロックにマウスを重ねると、右上にコピーのボタンが出る。ボタンを使うと、コードブロックの中身だけを過不足なくコピーできる（手でドラッグして選ぶと、先頭や末尾の行が欠けやすい）。

`setup.py` の `entry_points` や `CMakeLists.txt` のように、**既にあるファイルに数行を足す**指示もある。その場合は、ファイルを作り直さず、指示された位置に行を足す（4節）。

以下では、フェーズ3-1の `talker.py` を例にする。フェーズ2で `learn_py` パッケージを作ってあることが前提である。

## 2. 方法A: `touch` と `nano` で貼り付ける

### 2-1. ファイルを作る

```bash
cd ~/ws/src/learn_py/learn_py

touch talker.py

ls
```

**期待する結果**（並び順は環境の言語の設定によって変わる）: `cd` と `touch` は、成功しても何も表示しない。`ls` の一覧に `talker.py` が加わる。

```text
hello.py  __init__.py  talker.py
```

- `touch` は、中身が空のファイルを作るコマンドである。次の `nano` でもファイルは作られるが、先に `touch` で作って `ls` で確かめておくと、ファイル名の打ち間違いや、置く場所の間違いに早く気づける。
- `cd` で「No such file or directory」と出る場合は、フォルダがまだ無い。手順書に「フォルダを作る」とある場合は、`mkdir -p` で作ってから `cd` する。

### 2-2. `nano` で開いて貼り付ける

```bash
nano talker.py
```

**期待する結果**: ターミナルの画面が `nano` に切り替わる。1行目に `GNU nano 7.2` とファイル名が表示され、中身は空。画面の下の2行に、`^G Help`・`^O Write Out`・`^X Exit` などの操作の一覧が出る（`^` は `Ctrl` キーのこと）。

1. GitHubのページで、コードブロックのコピーのボタンを押す。
2. `nano` の画面で、`Ctrl+Shift+V`（またはマウスの右クリック）で貼り付ける。Windows Terminalで長いコードを貼り付けると、貼り付けてよいかを確かめる画面が出ることがある。その場合は、貼り付けを選ぶ。
3. `Ctrl+O` を押す。画面の下に `File Name to Write: talker.py` と出るので、`Enter` で保存する。`[ Wrote 36 lines ]` のように、書き込んだ行数が表示される（行数はコードによって変わる）。
4. `Ctrl+X` で `nano` を終わり、ターミナルに戻る。

- 保存せずに `Ctrl+X` を押すと、`Save modified buffer?` と聞かれる。`Y` を押すと保存（その後にファイル名の確認で `Enter`）、`N` を押すと保存せずに終わる。
- 貼り付け先の `nano` は、既定では行頭の字下げを自動で足さない（Ubuntu 24.04の `nano` の設定）。そのため、Pythonの字下げは、コピーしたとおりに入る。
- `Ctrl+V` は、`nano` では「次のページへ移動」の操作である。貼り付けには `Ctrl+Shift+V` を使う。

### 2-3. 中身を確かめる

```bash
head -5 talker.py
```

**期待する結果**: 貼り付けたコードの先頭の5行が表示される。手順書のサンプルの先頭と同じなら、貼り付けは成功している。

```text
import rclpy
from rclpy.executors import ExternalShutdownException
from rclpy.node import Node
from std_msgs.msg import String

```

- 何も表示されない場合は、保存していない（2-2の手順3を飛ばした）か、別の名前で保存している。`ls` でファイル名を確かめ、`nano talker.py` からやり直す。
- 表示が手順書と違う場合（先頭の行が欠けている等）は、ファイルを消して作り直してもよい: `rm talker.py` の後、2-1からやり直す。

## 3. 方法B: VS Codeで開いて貼り付ける

VS Codeは、Windows側に入れたまま、**WSLの中のファイルを直接開いて編集できる**。そのために、VS Codeの拡張機能「WSL」（Microsoft製）を使う。

### 3-1. 準備（最初の1回だけ）

1. Windows側にVS Codeを入れる（WSLのUbuntuの中には入れない）。
2. VS Codeの拡張機能の画面で「WSL」を探し、Microsoftが提供しているものを入れる。

### 3-2. ワークスペースを開く

Ubuntuのターミナルで、ワークスペースに移動してから `code .` を実行する（`.` は「今いるフォルダ」の意味）。

```bash
cd ~/ws

code .
```

**期待する結果**: VS Codeのウィンドウが開き、左の「エクスプローラー」に `ws` の中身（`src` など）が並ぶ。ウィンドウの左下に `WSL: Ubuntu-24.04` のように表示されていれば、WSLの中のファイルを開いている。初めて実行したときは、WSLの中にVS Code用の部品（VS Code Server）を入れるため、ターミナルに導入の進み具合が表示され、少し時間がかかる。

- Windowsのエクスプローラーから `\\wsl.localhost\...` のパスをたどって開く方法もあるが、この教材では `code .` を使う。WSLの拡張機能を通さずに開くと、ファイルの読み書きが遅くなったり、ターミナルやビルドの結果とかみ合わなかったりすることがある。
- `code: command not found` と出る場合は、Windows側のVS Codeを入れた後に、WSLのターミナルを開き直す。

### 3-3. ファイルを作って貼り付ける

1. 左のエクスプローラーで、`src` → `learn_py` → `learn_py` と開く。
2. 内側の `learn_py` フォルダを右クリックし、「新しいファイル」を選んで、`talker.py` と入力して `Enter` を押す。
3. 開いた空のファイルに、GitHubのページでコピーしたコードを `Ctrl+V` で貼り付ける。
4. `Ctrl+S` で保存する。

**期待する結果**: エクスプローラーの `learn_py/learn_py/` の下に `talker.py` が並ぶ。保存前はタブのファイル名の横に `●` が付き、保存すると消える。ターミナルで `head -5 talker.py`（2-3と同じ）を実行すると、貼り付けたコードの先頭が表示される。

- VS Codeのウィンドウの中でも、`Ctrl+@`（日本語キーボードの場合）でターミナルを開ける。このターミナルはWSLのUbuntuのもので、`colcon build` などをそのまま実行できる。
- VS CodeのWSLの環境では、改行コードはLinuxの形（LF）で保存される。Windowsの形（CRLF）になっていると、スクリプトの実行でエラーになることがある。右下のステータスバーに `LF` と出ていれば問題ない。

## 4. 既にあるファイルに行を足す場合

`setup.py` の `entry_points` に1行を足す、`CMakeLists.txt` の `ament_package()` の前に数行を足す、といった指示の場合は、ファイルを開いて、指示された位置にカーソルを動かしてから貼り付ける。

- **`nano`**: `nano setup.py` で開き、矢印キーでカーソルを動かして、貼り付ける。行を探すときは `Ctrl+W` で文字を検索できる（例: `entry_points` と入力して `Enter`）。保存と終了は2-2と同じ（`Ctrl+O` → `Enter` → `Ctrl+X`）。
- **VS Code**: エクスプローラーからファイルを開き、指示された位置をクリックして貼り付け、`Ctrl+S` で保存する。`Ctrl+F` で文字を検索できる。

フェーズ2の2-7節のように、既にある行の文言を書き換える場合も、開き方と保存のしかたは同じである（`nano hello.py` で開き、書き換える文字の位置へカーソルを動かして直す）。

足す位置を間違えると、ビルドや実行でエラーになる。手順書に書かれた「どの行の後（前）に足すか」を確かめ、足した後に `cat` で前後の行と一緒に見直すとよい。
