# ros2MinimalPhysicalAi

フィジカルAI（センサで周りを知り、判断し、モータなどを動かすAI）の開発に必要な技術スタックを、ROS2の最低限の構成で一通り身に着けるための学習教材です。Windowsの上のWSL2に入れたUbuntu 24.04とROS2 Jazzyを使います。ゴールは2段階です。最初のゴールは、「慣性のある車両を、目標の速度に追従させるシミュレーション」をROS2のノードで組み立てること（フェーズ5）です。最終ゴールは、その制御を、強化学習で学習させたニューラルネットワーク（NN）に置き換えてROS2のノードとして動かし、元の制御と同じ物差しで比べること（フェーズ7-5）です。

![教材の全体像。上の大きな枠が最初のゴールの「慣性のある車両を、目標の速度に追従させるシミュレーション」で、目標速度のノード、PI制御のノード、車両（自作の疑似プラント、またはGazeboの物理）が、目標速度・ペダル・速度でつながる閉じたループになっている。枠の右上には、速度が目標に追いつくグラフと走る車の挿絵がある。その下に道のりの4段階、STEP 1 基礎（フェーズ0〜4）・STEP 2 制御（フェーズ5）・STEP 3 評価（フェーズ6）が必須として、STEP 4 AI（フェーズ7）が最終ゴールまでの段階として左から右に並び、制御から「最初のゴールに到達」、評価から「記録して判定」の矢印が最初のゴールへ伸びている。STEP 4の「ROS2のノードに」が最終ゴールで、「二足歩行への橋渡し」は発展である。一番下の土台の帯には、実行環境（Windows 11 + WSL2 + Ubuntu 24.04 + ROS 2 Jazzy + Gazebo）、強化学習（Stable-Baselines3、別の仮想環境）、マシン（専用のGPUは不要）、言語（PythonとC++）が並ぶ](docs/img/readme_overview.svg)

上の図は、この教材の全体像です。フェーズ0〜4で基礎を固め、フェーズ5で最初のゴールの車両シミュレーションを組み立て、フェーズ6で記録して評価します。その先のフェーズ7で、制御を強化学習とニューラルネットワークに置き換え、ROS2のノードとして動かすところ（フェーズ7-5）が最終ゴールです。最終ゴールの一式の構成は、下の「[この教材のゴール](#この教材のゴール)」にあります。各フェーズの詳しい順番は「[読む順番](#読む順番)」にあります。

各手順書では、コマンドや実行手順の直後に「期待する結果」（表示の例と、その読み方）を書いています。そのため、ROS2の環境を用意せずに読み物として読むこともできます。この方針はすべての手順書に共通です。各ページの冒頭には、そのページの表示の出どころ（実際に実行して確かめた表示か、コードと仕様から想定した表示か）だけを「期待する結果の出どころ」として書いています。時刻・プロセスの番号・パス・数値の細部は、実行するたびに変わります。実機の表示と違う場合は、実機の表示を優先してください（「[確認の状況](#確認の状況)」）。

## GitHubで読む

この教材は、**GitHubのページを開いて読むことを前提**にしています。リポジトリをcloneしたり、ファイルをダウンロードしたりする必要はありません。

- **手順書の間の移動**: 手順書の中の他の文書への参照は、リンクになっています。クリックすれば、その文書が開きます。
- **コマンドとサンプルコード**: コードのブロックにマウスを重ねると、右上にコピーのボタンが出ます。コマンドは1行ずつ空行で区切っているので、1行だけを選んでコピーすることもできます。サンプルコードは、手順書の指示に従って、自分のPCのファイルに貼り付けて使います。
- **練習用のファイル**: 練習で使うワークスペース（`ros2_ws/`。ホームディレクトリの下の `~/ros2_ws`）とその中のコードは、フェーズ2から各自のPCで一から作ります。このリポジトリから取ってくるものはありません。
- **図**: 図はSVGの画像で表示されます。同じ内容のmermaid版の図も、図の下の「同じ図（mermaid版）」を開くと表示されます。画面のスクリーンショット（フェーズ5-0の冒頭のGazeboの画面）は図ではないので、mermaid版はありません。このREADMEの冒頭の全体像の絵も、アイコンや挿絵を含むポンチ絵で、mermaidでは同じものを描けないため、mermaid版の代わりに代替テキストと説明の文を添えています。

## この教材を作った理由

筆者は、ROS2の本を1冊読んだり、講座を1つ受けたりしただけでは、ROS2を使えるようになりませんでした。振り返ってみると、つまずいた原因は次の4つにあったと考えています。

**ROS2はミドルウェアなので、学んだ成果が目に見えにくい。** ROS2は、プログラム同士をつなぐための仕組みです。それ自体が何かを動かすアプリではありません。「トピックでメッセージが届いた」「ノードが一覧に出た」という練習を重ねても、自分が何を作れるようになったのかを実感しにくいのです。

**基礎から積み上げると、実際に使う場面までの道のりが長い。** 通信の種類、ビルドの仕組み、launch、パラメータと順に学んでいくと、どれも大事なことではあります。しかし、それらを組み合わせて何かを動かす場面にたどり着くまでに長い時間がかかり、途中で手が止まってしまいます。

**目標を決めずに進むと、豊富なエコシステムを追いかけるうちに挫折する。** ROS2の周りには、シミュレータ、可視化ツール、自律移動やロボットアームのためのパッケージなど、たくさんの道具があります。目指すものが決まっていないと、どれも学ぶべきものに見えてきます。それらを理解しようとしているうちに、息切れしてしまいます。

**入門書は、入口を広くするほど、ゴールがぼやけやすい。** 入門書は多くの読者の入口になるように、幅広い話題を少しずつ扱います。それ自体は入門書の役目ですが、1冊を読み終えたときに「何ができるようになったか」がはっきりしにくくなります。

そこでこの教材では、最初にゴールを2段階で決めました。最終ゴールは、目標の速度に追従する車両のシミュレーションを、ROS2のノードで組み立て、その制御を強化学習で学習させたNNに置き換えて比べる、という一式です（次の「この教材のゴール」の図）。その途中に、ROS2だけで組み立てられる最初のゴール（フェーズ5）を置きました。各フェーズは、この完成形に必要な部品を1つずつ手に入れる順番に並べています。必須の範囲は、最初のゴールと、それを記録で評価するフェーズ6までに絞りました。サービスやアクションのように、ゴールに直接使わない内容は任意にしています。周辺の道具も、ゴールに使うもの（Gazeboなど）だけを実際に動かし、ほかはフェーズ0で役割を紹介するだけにとどめています。

この教材は、ROS2のすべてを網羅するものではありません。1つの完成形を作りきって「ROS2で何かを動かせた」という足場を作り、そこから必要に応じて、公式ドキュメントや他の入門書で範囲を広げていくことを想定しています。

## この教材のゴール

最終ゴール（フェーズ7-5）で動かす一式は、次の図のとおりです。各箱の最後の行の、色の付いた文字は、その部品を作る（または使い方を学ぶ）フェーズです。ノード（ROS2の処理の単位）どうしは、目標速度・ペダル・速度のトピック（名前の付いた、一方向の通信の経路）でつながり、launchファイル（複数のノードをまとめて起動する設定）で一式を起動します。車両は、物理シミュレータのGazeboの中を走ります。Gazeboとの間は、ブリッジ（Gazeboの中の値とROS2のトピックを中継するノード）を通して、車輪のトルク（車輪を回す力）とオドメトリ（車両の位置と速さを表すデータ）をやり取りします。

最初のゴール（フェーズ5）では、制御器に、PI制御（目標との差と、その差の積み上げから、アクセルとブレーキの踏み方を決める古典的な制御）の `pi_controller` を置き、強化学習とNNの部品と、記録と指標の部品（フェーズ6で作る）を除いた一式を組み立てます。最終ゴールでは、`pi_controller` と同じトピックを受けて送る `nn_controller` を作り、ほかのノードのコードを変えずに、launchファイルの引数で入れ替えます（ワールドとプラントのパラメータは、NNを学習させたときの条件に合わせます）。NNの学習は、ROS2とは別に入れる強化学習（試した結果に点数を付け、点数が上がるように行動の決め方を学ばせる方法）のライブラリで行い、ROS2のノードは書き出した重みのファイルを読むだけです。各部品で使う技術と、それを学ぶフェーズの一覧は、[フェーズ0](docs/phase0_overview.md)の7節にあります。

## 対象読者

ROS2に初めて触れる人を対象にしています。ロボット工学の予備知識は要りません。次の2つを前提にしています。

**1. C++かPythonのどちらかで、プログラムを書いた経験があること**

クラスを定義して使う、関数を書く、といった基本的な書き方が分かれば十分です。両方の言語の経験は要りません。手順書のサンプルは、同じ仕様のノードをPython版とC++版で並べて載せています。そのため、片方の経験があれば、もう片方もサンプルと解説を読みながら追えるように書いています。ただし、C++はフェーズ2・3-1・4と間章（フェーズ4と5の間に置いた、任意の章）で使い、2つのゴールの部品（フェーズ5以降）はPythonで書きます。

**2. Linuxの基本的なコマンドを、十数個ほど使ったことがあること**

手順書では、次のようなコマンドを説明なしで使います。

| コマンド | 使う場面の例 |
|---|---|
| `cd` | 作業するフォルダへ移動する |
| `ls` | フォルダの中身を確かめる |
| `pwd` | 今いるフォルダを確かめる |
| `mkdir -p` | フォルダを作る |
| `cat` | ファイルの中身を表示する |
| `mv` | ファイルを移動する・名前を変える |
| `touch` | 空のファイルを作る |
| `rm` / `rm -rf` | ファイルを消す・フォルダを中身ごと消す（学習環境が手順書の内容とずれたときに、作ったものを消して作り直す） |
| `nano` または `vim` | ターミナルの中でファイルを書き換える（どちらか一方を使えればよい） |
| `grep` | 出力やファイルから、特定の文字を含む行を探す |
| `source` | 設定用のスクリプトを読み込む（ROS2では頻繁に使う） |
| `export` / `echo` | 環境変数を設定する・中身を確かめる |
| `sudo apt install` | パッケージを導入する |

`rm -rf` は、確認なしに中身ごと消し、元に戻せません。手順書の内容と自分の環境がずれて、作り直したいときに使います（たとえば、ワークスペースの生成物の `build/`・`install/`・`log/` を消してビルドし直す、作ったパッケージを消して作り直す）。実行する前に `pwd` と `ls` で、今いる場所と消す対象を確かめます。`sudo` は付けません。

ほかに、ターミナルを複数開いて並べて使うこと、動き続けるコマンドを `Ctrl+C` で止めること、VS Codeなどのテキストエディタでファイルを書くことにも慣れているとスムーズです。Linuxに触れたことがない場合は、先にこれらのコマンドを一通り試してから始めてください。

手順書のサンプルコードは、GitHubのページからコピーして、自分のPCの練習環境のファイルに貼り付けて使います。`touch` と `nano` を使う方法と、VS Codeを使う方法を、[サンプルコードを練習環境に置く方法](docs/howto_place_code.md)にまとめています。そのまま貼り付けて使うことを想定しているので、コードを隅々まで暗記する必要はありません。各行が何をしているかは解説を読んで理解し、書き方そのものは、必要になったときにサンプルを見返せば足ります。

また、サンプルは学習の要点が見えやすいように、エラー処理を最小限にしています。想定していない値（たとえば時定数に0）を与えるとノードが止まることがありますが、止まるのはシミュレーションだけで、起動し直せば元に戻ります。実務のコードでは、入力の検証をもっと厚くします（例は[フェーズ5-1](docs/phase5_1_plant.md)の5-1節の「補足: 起動時の値を検証していない理由」）。
